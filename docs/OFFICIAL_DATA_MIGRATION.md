# データソース移行記録：BoatraceCSV → BOATRACE公式（2026-11-20）

## 背景

旧データソース BoatraceCSV のデータ用リポジトリ `boatracecsv.github.io` が消滅し、
`https://boatracecsv.github.io/data` への全fetchが404になった。サイトのフロント
（ブラウザから直接CSV取得）と裏側スクリプトの双方が同ソース依存だったため、
`public/daily-trends.json` は2026-11-05で凍結し、予想の締切前固定も停止した。
取得スクリプトは404をログに残すだけで正常終了する設計だったため、ワークフローが
緑でもデータは死んでいる状態が続いた。

本移行では、締切時刻パイプライン（バックエンドが取得・変換してrepoにコミットし、
フロントは自サイトのデータを読む）と同じ形に全データセットを寄せた。

実地確認（2026-11-20）:
- B/Kファイルは `https://www1.mbrace.or.jp/od2/{B,K}/YYYYMM/{b,k}YYMMDD.lzh` から取得可能。
  ただしAkamaiの bot 対策で **存在するファイルでも間欠的にHTTP 403** が返る
  （日付による恒常的な不可用ではないことを複数日で確認）。取得は指数バックオフ付き
  リトライ（最大5回）で実装した。
- 公式レースページ（racelist / beforeinfo / odds3t）も同様に間欠403があり、リトライで取得可能。
- パーサは実ファイルで検証済み（例：2026-11-19 大村1Rの3連単オッズ 3-5-1 = 97.0 が
  Kファイル払戻 9,700円と一致）。ユニットテストは `tests/official-data.test.mjs`。

## パイプライン

- `scripts/official-data.mjs`：取得・変換・CSV出力（`public/data/<dataset>/YYYY/MM/DD.csv`、
  移行前と同一の日本語ヘッダ形式）。
- 朝の番組表生成：`.github/workflows/update-programs.yml`（07:30 / 08:35 JST）。
  capture-prospective は当日の番組表が無ければ自ら生成してから固定する（自己回復）。
- 結果生成：`daily-result-trends.yml` が集計前に直近3日分のKファイルを取り込む。
- 直前情報・オッズ：`.github/workflows/update-previews.yml`（08:00–21:59 JST、30分間隔）。
  締切まで3時間以内のレースだけを対象に収集し直すため、旧フィードのような
  「全レース分を朝に一括」ではなく、締切が近いレースから順に埋まる。
  過去日の previews は再収集しない（結果・出走表のみバックフィル対象）。
- バックエンドの集計スクリプトはHTTPではなく checkout 内のCSVを読む
  （`scripts/local-data.mjs`）。フロントは `csv.js` の `DATA_ROOT='public/data'` で自サイト配信を読む。

## waku10 の定義（移行に伴う変更）

旧フィードの集計仕様は提供元消滅により確認できないため、以下の自前定義に置き換えた。
モデルの重み付けが小さい特徴（枠番別勝率 .11 / 枠番別ST .035 / 直近10走 .05）だが、
数値の意味が変わった点は明記する。

- 対象：選手×枠番（艇番）ごとの全場成績（当地別ではない。当地同枠は従来どおり履歴集計が別に担う）
- 集計窓：2026-05-01以降に公式Kファイルから取り込んだ全結果（`data/frame-index.json` に蓄積）
- 枠番別勝率 = 1着回数 / 出走回数 × 10（勝率スケール）
- 枠番別平均ST = スタートタイミングの平均（フライングは実測STで算入）
- 枠番別平均スタート順 = ST昇順の順位（フライングは最後尾扱い）の平均
- 過去N走_着順 = 直近最大10走の着順（フライングは `F`、失格は `S`）

## バックフィル範囲（移行時に一回限り実施）

- フレーム履歴インデックス：2026-05-01 〜 2026-11-19 のKファイルを日付順に再生
- results/realtime・payouts のCSV：2026-08-23 〜 2026-11-19
- programs（Bファイル由来＋waku10）：2026-10-29 〜 2026-11-19
  （締切前固定の照合期間を復旧するため。出走表ページによる完全項目の補完は当日分のみ）
- daily-trends の欠落期間 2026-11-06 〜 2026-11-19 は上記結果CSVから再集計

## 凍結バックテストへの影響

`public/backtest.json` は旧フィードで実施した検証の凍結証拠であり、数値は変更していない。
その `modelHash` は実施時点のモデル（analytics.js / csv.js / backtest.js）のハッシュで、
今回 csv.js のデータ取得部が変わったため現行ファイルとは一致しなくなった。
`tests/backtest-report.test.mjs` は報告書改竄検出のため、ハッシュを移行前の
固定値と照合する形に変更した（モデルの計算式自体は無変更）。

## 既知の制限

- 公式Kファイルは全レース終了後に公開されるため、当日の結果・払戻は翌日扱いになる
  （従来のリアルタイム結果フィードとは異なる。当日の確定結果表示は翌朝までに反映）。
- previews/od3 は締切3時間前から30分間隔の収集のため、旧フィードより更新粒度が粗い。
- 中止情報はBファイルに含まれないため、当日分の title の中止状態は空欄のまま
  （締切時刻は boatcast 側の情報で補完される）。
- 気温・水温はKファイルに無いため results 側は空欄（sui には直前情報から入る）。
